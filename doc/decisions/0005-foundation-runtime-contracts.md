# 0005: foundation契約と実装

設計revisionを `nepl3-design-2026-09-06-r4` とする。r3のメタデータ検査から実際の共通runtimeへ進む際、source同一性、報告と予算、descriptor、値と参照の未定義部分を具体化した。履歴資料と過去revisionの判断は書き換えない。

URIをsource同一性として使うと、同じlocatorを持つ独立したmemory documentを区別できない。SourceRefはhost指定のopaque ID/revision/digest、SourceContentは別のURIと元byte列を持つ。共有操作は受け入れ済みsnapshotを一度だけ計上し、nativeとwireで入力予算の意味を合わせる。

LimitsとUsageを分離し、失敗・停止・中断でも消費済み予算を保持する。traceの件数超過はStopped(EventLimit)とし、列外の単一のtruncation報告で上限0も扱う。既存eventを上書きせず、先に確定した停止理由を維持する。

実際のTypeDescriptor/SchemaDescriptor、canonical JSONとSHA-256、registryの全参照finalizeを実装する。自己・foreign参照は記号で保持する。`nepl3.foundation` のdescriptorはcontractsから生成し、同じproduction registryで検査する。通常fieldのSchemaRefはこのpackageのRecord、NDF headerのSchemaRefは既定の裸tupleとして区別する。

共通syntax/view/Origin/environmentはそれぞれ局所ID空間とsourceの対応を持つ。graph検査と、Grammarのform/categoryやdomain意味の検査は別の証明とする。SourceMapはbyte/anchorの対応を検査し、粗いsnapshot依存で正しい写像をCycleとして拒否しない。

NDF codecはすべてのintrinsic tag、canonical整数・有理数、field配列とschema header、制限されたCBOR、schema照合を扱う。深い値の走査・後始末をnative再帰に依存させず、shared Budgetへ計上する。provider/reader/engineの操作変換、全形式のconformanceと最終製品は引き続き実装する。

実行した試験と残課題は [foundation実装記録](../progress/foundation-runtime.md) に残す。この判断とcrateの存在をT01/T02や処理系全体の完了証拠にしない。
