# 18\. HTMLを先行利用\[せんこうりよう\]する実装段階\[じっそうだんかい\]

この章\[しょう\]はHTML生成\[せいせい\]の各層\[かくそう\]の接続\[せつぞく\]と、先行利用\[せんこうりよう\]の範囲\[はんい\]を定\[さだ\]める。構文\[こうぶん\]を印字\[いんじ\]するsource printerをHTML rendererへ読\[よ\]み替\[か\]えない。採用\[さいよう\]の経緯\[けいい\]は設計判断\[せっけいはんだん\]0006、現在\[げんざい\]の実装状態\[じっそうじょうたい\]はimplementation\-status\.jsonを参照\[さんしょう\]する。

<a name="実装依存"></a>

## 実装依存\[じっそういぞん\]

H0〜H3はT22〜T25に対応\[たいおう\]する作業段階\[さぎょうだんかい\]であり、順序\[じゅんじょ\]・成果物\[せいかぶつ\]・受入条件\[うけいれじょうけん\]の正本\[せいほん\]はdesign\/tasks\.jsonとする。各段階\[かくだんかい\]では利用\[りよう\]する前段\[ぜんだん\]の実\[じつ\]APIを検証\[けんしょう\]し、空\[から\]のfragmentで未実装\[みじっそう\]を隠\[かく\]さない。T22はT01〜T09の全体完了\[ぜんたいかんりょう\]を着手条件\[ちゃくしゅじょうけん\]にせず、T23では未対応\[みたいおう\]embedを型付\[かたつ\]きで拒否\[きょひ\]し、T24でMathの実解決\[じつかいけつ\]を追加\[ついか\]する。

各層\[かくそう\]の詳細契約\[しょうさいけいやく\]は、Docの意味\[いみ\]・構造\[こうぞう\]が05章\[しょう\]、数式表示\[すうしきひょうじ\]が17章\[しょう\]、型付\[かたつ\]きmarkupとserializerが19章\[しょう\]、DocのprepareとHTML変換\[へんかん\]が20章\[しょう\]、集合\[しゅうごう\]のpage・anchor解決\[かいけつ\]が21章\[しょう\]である。15章\[しょう\]は生成済\[せいせいず\]み文書\[ぶんしょ\]の配置\[はいち\]と公開\[こうかい\]、16章\[しょう\]は正式文書\[せいしきぶんしょ\]の正本切替\[せいほんきりかえ\]を所有\[しょゆう\]する。以下\[いか\]はそれらの接続\[せつぞく\]に必要\[ひつよう\]な保証\[ほしょう\]の要約\[ようやく\]であり、各層\[かくそう\]の独立\[どくりつ\]した検査\[けんさ\]を置\[お\]き換\[か\]えない。

T10・T11・T13・T15・T17・T18は先行経路\[せんこうけいろ\]を再利用\[さいりよう\]して、当初\[とうしょ\]の全責務\[ぜんせきむ\]を実装\[じっそう\]する。Math evaluate、Circuit、LSP、汎用\[はんよう\]provider、reference profileのUI、Pages全受入\[ぜんうけいれ\]、T21文書移行\[ぶんしょいこう\]の完成\[かんせい\]を先行利用\[せんこうりよう\]の成功\[せいこう\]から推定\[すいてい\]しない。T16はT25と既存\[きそん\]の最終依存\[さいしゅういぞん\]、すべてのrequired受入条件\[うけいれじょうけん\]を要求\[ようきゅう\]する。

## H0\/H1の契約\[けいやく\]

Docの既存\[きそん\]arenaは表\[ひょう\]・list・page link・relative link・external link・imageなどを保持\[ほじ\]するが、構造\[こうぞう\]proofやCheckedLabelsは完全\[かんぜん\]なPreparedArticleではない。文書検査\[ぶんしょけんさ\]は、表示対象\[ひょうじたいしょう\]language・parallel policy、外部\[がいぶ\]page・asset・foreign requirementsを明示\[めいじ\]する。prepareは対象\[たいしょう\]documentのidentity、全要求\[ぜんようきゅう\]、解決結果\[かいけつけっか\]の型\[かた\]・位置\[いち\]・資源閉包\[しげんへいほう\]\{resource closure\}を照合\[しょうごう\]する。backendへ未解決\[みかいけつ\]slotやhostの任意\[にんい\]HTMLを渡\[わた\]さない。

markupは、table・header・cell、ordered・unordered listとstart・checkbox、img・alt・caption、一般\[いっぱん\]linkに必要\[ひつよう\]な要素\[ようそ\]・属性\[ぞくせい\]・内容\[ないよう\]モデルを、閉\[と\]じた型\[かた\]として持\[も\]つ。同\[どう\]artifactのanchor、page ID、相対\[そうたい\]path、external URI、asset参照\[さんしょう\]を区別\[くべつ\]する。危険\[きけん\]scheme、path traversal、重複\[ちょうふく\]path、未宣言\[みせんげん\]asset、偽\[にせ\]digest、wrong slotを拒否\[きょひ\]し、I\/O権限\[けんげん\]はhostに残\[のこ\]す。

Paragraphを入\[い\]れ子\[こ\]のpへ機械変換\[きかいへんかん\]せず、文\[ぶん\]のrunと子\[こ\]blockのwrapperを使\[つか\]う。Sentence間\[かん\]に空白\[くうはく\]を追加\[ついか\]しない。Ruby・Anno、Parallel、heading、空\[から\]の表\[ひょう\]、list start、codeの改行\[かいぎょう\]、画像\[がぞう\]の代替説明\[だいたいせつめい\]を保持\[ほじ\]し、ブラウザparserのtree補正\[ほせい\]で意味\[いみ\]が変\[か\]わっていないか確認\[かくにん\]する。一般\[いっぱん\]DocとKaTeXの双方\[そうほう\]を、検査済\[けんさず\]みmarkupとserializerへ通\[とお\]す。

## H2\/H3の契約\[けいやく\]と検証\[けんしょう\]

17章\[しょう\]を適用\[てきよう\]する。数式\[すうしき\]の正本\[せいほん\]は構造\[こうぞう\]であり、本文\[ほんぶん\]のdollar探索\[たんさく\]、MathMLからのTeX推測\[すいそく\]、source printer文字列\[もじれつ\]を数式\[すうしき\]として利用\[りよう\]しない。非結合\[ひけつごう\]operand、負号\[ふごう\]と累乗\[るいじょう\]、多文字\[たもじ\]Unicode記号\[きごう\]、片側\[かたがわ\]fence、Doc注記\[ちゅうき\]の忠実性\[ちゅうじつせい\]を共通試験\[きょうつうしけん\]へ結\[むす\]び付\[つ\]ける。表示\[ひょうじ\]のためにevaluateを実行\[じっこう\]しない。

実\[じつ\]\.nepldからHTMLまでのpositive・negative、MathML\-only、KaTeX不在\[ふざい\]、optional module失敗\[しっぱい\]、局所失敗\[きょくしょしっぱい\]と全体\[ぜんたい\]Stopped、安全性違反\[あんぜんせいいはん\]、asset不足\[ふそく\]を検証\[けんしょう\]する。NodeとDOMなしの実\[じつ\]Workerで、固定版\[こていばん\]・入力\[にゅうりょく\]・設定\[せってい\]が同\[おな\]じ正準\[せいじゅん\]markup・manifestを生成\[せいせい\]することを比較\[ひかく\]する。

Chromium・Firefox・WebKitで、script禁止\[きんし\]かつsame\-origin権限\[けんげん\]なしのpreview、CSP・CORS・font・非\[ひ\]root path、古\[ふる\]い返信\[へんしん\]の拒否\[きょひ\]、停止\[ていし\]とepoch、同\[どう\]artifactのexportを実行\[じっこう\]する。書\[か\]き出\[だ\]し済\[ず\]みHTMLのJavaScript無効表示\[むこうひょうじ\]、offline bundle、zoom・狭\[せま\]い幅\[はば\]・印刷\[いんさつ\]・アクセシビリティtreeを確認\[かくにん\]し、DOMの存在\[そんざい\]だけを視覚組版\[しかくくみはん\]の成功\[せいこう\]にしない。WebKit自動試験\[じどうしけん\]とSafari・iOSの実機確認\[じっきかくにん\]を区別\[くべつ\]する。

各段階\[かくだんかい\]は、実\[じつ\]API・command・source・spec・target・ログ・独立\[どくりつ\]レビューと未検証範囲\[みけんしょうはんい\]を記録\[きろく\]する。既存\[きそん\]bootstrap、Doc source printer、source・Origin、予算\[よさん\]、no\_std・WASIの回帰\[かいき\]を維持\[いじ\]する。ローカルでの成功\[せいこう\]は、Pages公開\[こうかい\]の証拠\[しょうこ\]ではない。

## 正式文書\[せいしきぶんしょ\]のDoc移行\[いこう\]

T23で必要\[ひつよう\]な表現\[ひょうげん\]が使\[つか\]えるページから、T21の棚卸\[たなおろ\]し・変換\[へんかん\]を進\[すす\]める。数式\[すうしき\]を含\[ふく\]むspecは、T24の実生成経路\[じつせいせいけいろ\]を使用\[しよう\]する。T21はT19・T24全体\[ぜんたい\]の完了\[かんりょう\]を一括\[いっかつ\]の前提\[ぜんてい\]にせず、ページが使\[つか\]うDoc・Mathの操作\[そうさ\]ごとに必要\[ひつよう\]な実装\[じっそう\]と検査\[けんさ\]を確認\[かくにん\]する。NEPL3dを正式\[せいしき\]な正本\[せいほん\]とし、HTMLは再生成\[さいせいせい\]できる表示用\[ひょうじよう\]の出力\[しゅつりょく\]とする。Pages公開\[こうかい\]とrustdocの詳細監査\[しょうさいかんさ\]を、Docの本体開発\[ほんたいかいはつ\]・正本移行\[せいほんいこう\]を止\[と\]める条件\[じょうけん\]にしない。ページ単位\[たんい\]の意味\[いみ\]・リンク・安定\[あんてい\]ID・生成物対応\[せいせいぶつたいおう\]とbootstrapの条件\[じょうけん\]は、16章\[しょう\]のまま維持\[いじ\]する。README・AGENTSなどのMarkdown入口\[いりぐち\]は、必要\[ひつよう\]に応\[おう\]じて\.nepld正本\[せいほん\]から生成\[せいせい\]し、二重\[にじゅう\]手書\[てが\]き保守\[ほしゅ\]をしない。
