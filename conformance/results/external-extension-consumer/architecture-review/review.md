## Conclusion
A host assembled in another workspace can already register an independently named syntax schema and LanguagePackage, resolve its profile, parse using the production reader/engine, keep source/origin/diagnostic data and exchange validated trees through NDF. This does NOT establish a shipped drop-in plugin loader, general process provider, stable independently released crates, or every domain semantic operation.

## Implemented public surfaces
- core/source.rs: checked immutable UTF-8 SourceSnapshot, SourceId/revision/digest, checked Span, SourceStore/SourceAdmission and host-owned reservations. Public accessors, not mutable byte fields; filesystem/runtime I/O stays outside.
- core/schema.rs: arbitrary SchemaDescriptor package/revision/types/operations, ordered record fields and named references; register+finalize+validate. SchemaRef/OperationRef are data identities, not executable pointers. StructuralValue explicitly excludes domain constraints; constraint IDs remain owner obligations. Registering another digest for an existing package/revision conflicts. KindRef IDs must be obtained from the selected registry rather than hardcoded from Rust enum discriminants.
- core/diagnostic.rs and diagnostic/validation.rs: arbitrary schema-owned typed arguments, codes, stages, primary/related spans and report data. A report's claimed remote Usage is not absorbed by structural validation. Token/view, origin and bundle ownership checks are generic.
- reader/plan.rs: closed built-in primitive vocabulary is a foundation grammar, not a four-DSL registry. ReaderExpr/CharClass/Rule/Call/Map/Then plus versioned ProviderSignature support language-owned readers. TokenizationHost is a narrow native callback boundary; None retains owned suspension. Budget/continuation/source/report validation survives external placement.
- engine/package/model.rs and check.rs: arbitrary category/mode/form spelling/kind/field/leaf/namespace/binding and ExtensionRequirement. The facts/v1 signature is a common editor contract checked specially, not a Doc/Math allowlist. Unknown operation and mismatching signatures fail. LanguagePackage contains surface syntax; it is not a universal evaluator or renderer.
- engine/profile.rs+resolve.rs: explicit LanguageRegistration and RuntimeCatalog of package/provider/resource identities, schema closure, allowlist and operation limits. Provider identity claims in a profile do not create host registrations.
- engine parse/binding/facts/analysis and portable modules: public parsing, native host dispatch, borrowed proofs, tree/recovery/selection and editor data adapters. wire encode_checked/decode_checked compose with engine typed adapters via FoundationCodec; engine and reader production depend only on core/reader, not wire. No domain-name branches found by source scan plus direct reading of registries/checkers.

## Designed or incomplete surfaces
- interfaces/engine.json has LanguagePackage/ParseProfile structural schemas, but engine/portable exposes tree/head/binding/facts/query/region/rename/analysis modules, not a ready typed LanguagePackage/Profile codec/loader. A caller can construct native descriptors/packages now; interoperable distributable package loading still needs a validated boundary, not Rust memory serialization.
- Foundation descriptor lists Invoke/Resume/OperationReply and spec09 defines full Invoke/Resume/Reply/Cancel/Close, 8-byte framing, replay/cycle/continuation rules. There is no apps/provider or production suite member at this base. OperationResult<T> and specialized reader/engine outcomes do not constitute the complete generic operation dispatcher. T11/T12+ remaining status is not overridden.
- Reader request NDF loopback and saved-Transform-reply adapters are implemented. spec09 explicitly leaves generic Read operation-reply envelopes, initial provider requests, full Await/process transport incomplete; don't infer them from one tested adapter.
- An external DSL must still own lower/check/domain model, domain constraints, operation semantics and adapters. Generic grammar does not infer a simulator/renderer. Grammar compiler is separately available but is not a foundation dependency or prerequisite to manually registering a LanguagePackage.

## Cargo and schema compatibility are different
Current workspace.package is 0.1.0, publish=false with inherited metadata and path workspace dependencies. Whole checkout path dependencies work in the independent workspace. Copying one crate directory alone loses its workspace inheritance; crates.io publication and Git dependency fetch were not tested. Consumer Cargo.lock governs its resolved graph (a dependency repository lockfile is not transitively enforced). Use one exact source/revision for the common foundation crates; duplicate package sources/versions can yield incompatible Rust types even if names match. Rust native calls assume source-level API compatibility within that build; no stable dynamic Rust ABI is offered. Wire compatibility instead requires schema package/revision/digest, explicit field order, typed codec and invariant validation. Matching Rust version alone or decoding NDF alone does not establish operation compatibility.

## Independent execution
external/src/main.rs assembles audit.external.syntax/AuditExternal and a declare form, parses `declare alpha beta`, asserts three nodes, source revision7, root kind/head end7 and no diagnostics, then validates a typed NDF ParseTree roundtrip; wrong expected type and unknown operation reject. Fixture declaration helper is adapted from existing public engine support (renamed schema), explicitly not a newly claimed independent grammar compiler. Native/portable field expectations in main are reviewer-authored.
External tests/parse* and reader_portable.rs are byte copies of existing tests: six native-host cases and two reader native/NDF cases rerun outside the original workspace. Their expectations are inherited and their purpose here is public-API/dependency isolation, not independent semantic oracle. First probe compile used private fields and a guessed operation method; corrected to public accessors and Package check. This helper error is excluded, preserved in probe-first.log/probe-first.rs.
The no_std external library calls checked wire exchange and compiles for thumbv6m-none-eabi; this is compile evidence, not bare-metal execution.

## Recommended first production slice
Keep the initial independent Hello workspace with fixed repository dependencies and explicit checked schema/package/profile construction. Require native parse and NDF semantic comparisons, Unicode/source positions, malformed/unknown input, cancellation/limits, generated-source/diagnostic closure and wrong schema/provider identity negatives. Keep it outside the workspace member graph and inspect cargo metadata to prevent accidental tools/domain dependencies. Register the result as an external-consumer API regression, not a release or generic plugin acceptance.
Next use a small external custom reader/facts operation, with the same OperationRef and checked native/NDF request/reply tests; then add package/profile artifact loading and per-operation host dispatch where required. Retain typed per-operation adapters and finite shared budgets. Do not introduce a giant Language trait, dynamic Rust ABI, unrestricted Any dictionary or relocate Source/Origin ownership into each DSL.

Unverified: dynamic library loading, network/Git fetch, crates.io release, complete process protocol, all DSL algorithms, browser integration, all T16 acceptance. No release/canonical/deploy action was performed.
