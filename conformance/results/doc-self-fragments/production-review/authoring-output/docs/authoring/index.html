Doc文書ぶんしょの執筆指針しっぴつししん

この指針ししんは、NEPL3の例れい・仕様しよう・解説かいせつをDocで書かくときの表記選択ひょうきせんたくを定さだめる。Doc仕様しようの構文こうぶん・意味いみを変更へんこうするものではない。正式文書せいしきぶんしょの正本切替せいほんきりかえは移行条件いこうじょうけんに従したがう。

Sentence literalを標準ひょうじゅんにする場面ばめん

本文ほんぶんがText・Ruby・Annoで表あらわせる場合ばあいは、読よみやすいsentence literalを基本きほんとする。通常つうじょうの説明文せつめいぶん、見出みだし、表ひょうのセル、対応文たいおうぶんのvariantに使つかえる。Ruby・Annoの入いれ子こだけを理由りゆうに前置構築ぜんちこうちくへ展開てんかいする必要ひつようはない。

一ひとつのliteralは一ひとつのSentenceである。本文ほんぶんでは著者ちょしゃが対応たいおうさせたい文ぶんごとに分わける。見出みだしや表ひょうのセルは短みじかい語句ごくでもSentenceとしてよい。句点くてんの数かずから処理系しょりけいが自動分割じどうぶんかつする規則きそくは設もうけない。

literal内ないにソース上じょうの直接改行ちょくせつかいぎょうは書かかない。文書ぶんしょの明示的めいじてきな改行かいぎょうには明示的めいじてきな改行かいぎょうのbreakを使つかい、そのSentenceは前置構築ぜんちこうちくにする。\nはTextのデータとしてLFを保持ほじするescapeであり、文書構造ぶんしょこうぞうの改行かいぎょうを表あらわす標準表記ひょうじゅんひょうきにはしない。引用符いんようふは \"、backslashは \\、文字もじとしての注釈区切ちゅうしゃくくぎりは \[ などでescapeする。画面幅がめんはばに応おうじた折返おりかえしは表示側ひょうじがわに任まかせる。長ながい一文いちぶんは、それだけを理由りゆうに別べつの対応単位たいおうたんいへ分割ぶんかつせず、編集へんしゅうしにくい場合ばあいに前置構築ぜんちこうちくを選えらぶ。

明示的めいじてきなsentence構築こうちくを選えらぶ場面ばめん

strong・em・ref・anchor・link・Inline位置いちのcode・画像がぞう・Mathなど、literalにないInlineを含ふくむSentenceは前置構築ぜんちこうちくで表あらわす。明示めいじBreakが必要ひつような場合ばあいも同様どうようで、Text内ないのLFへ置換ちかんしない。

複雑ふくざつな注釈ちゅうしゃくの各部分かくぶぶんを編集へんしゅう・比較ひかくしたい場合ばあいや、constructor API・構文こうぶんの解説かいせつを示しめす場合ばあいにも前置構築ぜんちこうちくを使つかえる。機能きのうを見みせるためだけに通常つうじょうの本文ほんぶんすべてを展開てんかいする必要ひつようはない。プログラムから文書ぶんしょを生成せいせいするときは、型付かたつきconstructorで意味構造いみこうぞうを作つくり、ソース文字列もじれつの連結れんけつと再解析さいかいせきを前提ぜんていにしない。

text "..." の引用部分いんようぶぶんは通常つうじょうTextであり、sentence literalの注釈構文ちゅうしゃくこうぶんを再解釈さいかいしゃくしない。前置構築ぜんちこうちくでRuby・Annoが必要ひつようなら、それぞれのconstructorを使つかう。Sentence literalはSentenceであってInlineではないため、sentenceのInline列れつへそのまま挿入そうにゅうしない。

明示的めいじてきな改行かいぎょうはbreak

breakは引数ひきすうを持もたないInline constructorである。同おなじSentenceの途中とちゅうで改行かいぎょうするために使つかい、Sentenceやparagraphの境界きょうかいを増ふやさない。HTMLではbr、plain text抽出ちゅうしゅつではLFになる。段落だんらくを分わけたい場合ばあいはparagraphを作つくる。空からの段落だんらくや複数ふくすうのbreakを余白調整よはくちょうせいに使つかわない。

既存きそんのText内ないLFやRawCodeの元もとの改行かいぎょうは、内容ないようを保たもつためにそのまま保持ほじする。breakとの自動相互変換じどうそうごへんかんはしない。Compact printerも、breakを含ふくむSentenceをliteralへ押おし込こまない。改行かいぎょうの例れいでは、日英にちえいの対応文たいおうぶんそれぞれにbreakを置おいている。

sentenceとparallelの使つかい分わけ

多言語たげんごの本文ほんぶんは文単位ぶんたんいで parallel を作つくり、各かく variant にその言語げんごのSentenceを置おく。段落全体だんらくぜんたいを一ひとつの対応文たいおうぶんに詰つめ込こまない。各言語かくげんごは意味いみが対応たいおうする自然しぜんな文ぶんにし、語順ごじゅんや単語数たんごすうの一致いっちを要求ようきゅうしない。

variantごとにliteralと前置構築ぜんちこうちくを選えらべる。一方いっぽうの言語げんごに構造こうぞうが必要ひつようでも、他方たほうまで機械的きかいてきに同おなじ表記ひょうきへ変換へんかんしない。強調きょうちょうや参照さんしょうを付つける場合ばあいは、対応言語たいおうげんごでも意味いみと参照先さんしょうさきが一致いっちするか確認かくにんする。翻訳ほんやくがない場合ばあいを空からSentenceでごまかさず、空からの翻訳ほんやくを意図いとする場合ばあいだけ空からSentenceを使つかう。

線型結合せんけいけつごうの例れいは両経路りょうけいろを学まなべる例れいとして、最初さいしょの対応文たいおうぶんにliteral、続つづく対応文たいおうぶんに明示的めいじてきなsentence構築こうちくを残のこす。本文ほんぶんの対応単位たいおうたんいはどちらも同おなじである。

RubyとAnnoの対象たいしょう

日本語にほんごの振ふり仮名がなはGlossのRuby指針ししんに従したがい、漢字部分かんじぶぶんに付つける。送おくり仮名がな・助詞じょし・片仮名かたかな・数字すうじ・記号きごうを漢字かんじと一緒いっしょにRubyの本体ほんたいへ包つつまない。読よみは文脈ぶんみゃくに合あう語ご・漢字部分かんじぶぶんの単位たんいで付つけ、漢字一文字かんじひともじずつへの分割ぶんかつを強制きょうせいしない。

語句全体ごくぜんたいの訳語やくご・意味説明いみせつめいはAnnoに置おく。例たとえば {[原点/げんてん]を[通/とお]る[直線/ちょくせん]/a line through the origin} とする。前置構築ぜんちこうちくではAnnoのbaseをConcatで組くみ、その子こをRubyとTextに分わける。カタカナ語ごは {ベクトル/vector} のように意味注釈いみちゅうしゃくを付つけられる。

これは日本語文書にほんごぶんしょの執筆指針しっぴつししんである。中国語ちゅうごくごのピンインや他言語たげんごの転写てんしゃなど、Rubyが扱あつかえる一般的いっぱんてきな音韻注釈おんいんちゅうしゃくをparserやschemaで禁止きんししない。

構造こうぞうと確認かくにん

話題わだいのまとまりはsection、連続れんぞくする本文ほんぶんはparagraph、列挙れっきょはlist、同おなじ項目こうもくを比較ひかくする情報じょうほうはtableで表あらわす。参照さんしょうには安定あんていしたsection/anchor IDを使つかう。機能きのうの使用数しようすうを増ふやすことを目的もくてきに、不要ふような装飾そうしょく・表ひょう・埋うめ込こみを足たさない。

表記ひょうきを変更へんこうしたときは本文ほんぶん・読よみ・注釈ちゅうしゃく・対応文たいおうぶん・強調きょうちょう・参照さんしょうを保たもつ。literalと前置構築ぜんちこうちくの等価性とうかせいは意味構造いみこうぞうで確認かくにんし、元もとソースの位置いちまで同一どういつだとは扱あつかわない。構造こうぞうauditの成功せいこうと、実じつparser・lower・HTML生成せいせいの成功せいこうも区別くべつする。資源停止しげんていしや未対応機能みたいおうきのうが残のこっている例れいは、実行可能じっこうかのうと広告こうこくせず制約せいやくを記録きろくする。
