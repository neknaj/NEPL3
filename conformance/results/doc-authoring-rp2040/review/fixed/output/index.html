ARMv6-M build and RP2040 execution

This outer test adapter links the production foundation crates for thumbv6m-none-eabi. Its separate Cargo workspace and lockfile keep HAL, startup, allocator and UART dependencies outside the production workspace. There is no emulator-specific NEPL3 implementation.

The initial firmware executes four production API checks: UTF-8/UTF-16 source positions with supplementary Unicode and CRLF, sticky budget exhaustion, NDF roundtrip, and malformed NDF rejection. Reader and engine dependencies compile; their complete runtime acceptance suites are not exercised by these four checks. This target does not promote any language or platform acceptance group.

Reproduce

From the repository root, with the pinned Rust toolchain, Python 3.13 and Node 24.14.1:

CI separates build and execution jobs and transfers the exact ELF, UF2 and build record. The execution job verifies both hashes before loading the UF2; it does not rebuild. build.json records the source file hashes, commit, rustc, Cargo and target; emulator.json records the UF2 hash, installed Node/rp2040js versions, protocol, test results and execution limits. execution.json links the build and execution records by SHA-256. A build commit alone is not the identity of an uncommitted local build: the input file hashes identify that case. Source hashes must match before and after building; concurrent source edits are rejected. These are execution records, not signed attestations.

The UART protocol is ASCII @NEPL3/1 BEGIN, one PASS/FAIL for every known test, then @NEPL3/1 END. Success requires every expected test exactly once and a terminal CPU wait. Missing, duplicate, unknown, malformed, failing or trailing records are rejected. Panic, an early CPU wait, break, 50 million instructions or 15 seconds of emulator work fail. A separate Python process watchdog kills and reaps the Node process after 30 seconds, including a stuck emulator call.

Scope and constraints

  • Only core 0 runs, interrupts remain disabled, and the 64 KiB aligned bump allocator never reclaims storage. It measures cumulative allocations across this small suite, not general-purpose heap performance. Physical exhaustion is a failing panic, not a successful logical resource stop.

  • The UF2 includes RP2040 boot2 and vectors. The runner enters the vector table directly: boot ROM, boot2 execution and actual hardware startup remain untested. disable-intrinsics avoids depending on emulator ROM routines.

  • Known PLL/UART startup warnings are recorded; other warnings and errors fail. Clock accuracy, peripherals, multicore behavior and physical hardware are outside this test's claim.

  • rp2040js is pinned to 1.3.3 with the npm lockfile. The converter accepts a restricted ELF32 little-endian ARM load image and emits family-tagged UF2. The loader validates all block headers and vector bounds before execution.

  • Browser execution, RISC-V and big-endian execution remain separate work. This lane cannot substitute for their required tests, WASI, or Doc rendering.
