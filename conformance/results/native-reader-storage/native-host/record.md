# Independent native reader drive and Doc source-cache review

Root implementation only; reviewer changed scratch files and performed no Git operations. Initial four files are in files.json, then runtime limits preservation, owned frame transfer, and host test formatting are in delta-files.json. final-files.json identifies the five final reviewed production files. The whole-snapshot storage change was reviewed previously and is not re-audited here.

Findings:
1. Confirmed regression in the first fast native dispatch: a Read -> Dependent host callback could replace Budget with a Budget having Work limit +1, preserve all observed Usage, and return a valid reply. Prior runtime/tokenizer code rejected it with host_error Continuation and an Await; initial fast code returned Token(Text("b")) with no host error. The same independent probe passed under the prior two production files and failed under the initial fixed files. This is loss of an existing native boundary check, not a claim of sandboxing arbitrary native machine code. Original/current/prior logs and probe are retained.
2. Root fix stores original Limits in Reader Machine, checks limits and monotonic Usage after the callback (including None), and materializes the full pending continuation on rejection with the original Machine limits. The original failure probe now rejects correctly. Restoring original limits while preserving observed Usage lets the same Await resume to Token("b"). Scope and request-limit echo forgeries are rejected before that valid retry. Additional independent modes reject a changed-limit None and observable Usage rollback. No blocking issue remains from this finding in the reviewed version.
3. A copied dependency initially contained core source.rs f4047ecc with pointer-position-dependent source admission cache Work. The existing raw-versus-sealed engine regression failed on let "x" "x": only Work differed (5100 versus5097), while all semantic data matched. Root identified and corrected the core cache separately. Exact source-only dependency delta e2d301f1 changes search/shift charges to length-derived bounds; same original engine regression then passes. Both source bytes, diff and before log remain in this evidence. Full core cache review is assigned to another reviewer; this record claims only the reproduced symptom and original-test retest.

Code review:
- Native Read and Dependent callbacks run while the original Reader Machine is owned. Provider call, frame phase, declared source closure, report/payload validation and application use the existing shared check_provider/apply_provider logic. Transform retains the saved pending-context path. A declined call is marked deferred so the outer tokenizer does not invoke it a second time.
- Non-stopping invalid replies retain the owned machine until finish builds the existing complete Await. Stopping callbacks/validation preserve the original typed stop reason and formal collector. Existing resume echo/source/usage checks remain on real external waits. Private fast dispatch does not accept an external native pointer or reconstructed execution proof.
- Owned ReaderFrame transfer into apply_provider moves frame.checkpoint for NoMatch/NeedMore. Borrowed validation precedes the pop/transfer. It changes storage copying, not rollback state or accepted artifact authority.
- The Doc cache reuses its private index only after the entire existing ordered source prefix compares equal with budgeted equality. Shrink, reordering or differing URI/content builds a replacement solely from the requested declarations. A failed replacement leaves the old cache, but provider returns the refresh error before using it. An interrupted append can retain a valid requested prefix; later calls still check their complete request scope. Context and provider implementation checks are not cached or skipped. No omitted cached source becomes resolver authority on a successful request.
- The fixed 5000 Work stop test was correctly replaced by four caps derived from a measured successful call of the same scenario. Optimization can make 5000 sufficient. The test still requires typed WorkLimit at each lower boundary and verifies no cap overrun; no production budget was increased.

Independent tests:
- A two-callback Read -> Dependent plan has ten host modes: normal, second-call None, semantic error, invalid payload, typed Cancelled error, cancelled None, actual NDF/CBOR request loopback, changed Limits with Some, changed Limits with None, and observed Usage rollback. Callback count is exactly two and caller depth restores to zero. Deferred/error paths preserve an Await suitable for checked retry. Before valid retry, wrong operation scope and request limit echoes fail. Successful native/fallback results agree by value.
- The loopback performs encode_checked -> actual CBOR -> decode_checked of the ReadRequest component, including the inner ReadRequest of DependentRequest. It reconstructs source declarations with a fresh empty receiver store, validates/restores the request, and compares every field before returning the real provider result. Dependent first value is independently asserted as Text("a"); this is not a claim of a complete general portable DependentRequest/ReadReply operation adapter.
- Cache tests exercise all six permutations of three sources, shrink, same-ID/revision different URI/content replacement, empty subsequent scope, every measured Work/Allocation threshold for append and replacement, and low-Work rejection of independently constructed storage. Successful stores equal exactly the current request's unique source order, SourceBytes is not added by cache refresh, and rejected partial state cannot satisfy the next empty request.
- Existing reader/engine tests cover Transform outcomes, provider report/source closure, rejected native/NDF replies and retry, candidate rollback, generated Text source maps, nested stopped reasons, close/cancellation, and source/plan/usage scoped continuations.
