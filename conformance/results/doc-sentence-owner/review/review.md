## Source/contract review

SentencePayload has the explicit schema field order value:DocValue, origins:List<Origin>, view:DocView(head, ViewBundle); no SourceSnapshot text or SourceMap is hidden in that record. Native helpers deliberately use the existing DocumentSyntax type with a narrower validator, as now documented. Generic DocumentSyntax's independent source closure and mapped-position path remain intact.

The decoder checks the selected named type/schema digest, builds a store containing only the explicit owner, admits that owner using the shared SourceAdmission, and decodes spans/origins/views through the scoped foundation codec. It then validates the Doc graph, local origin DAG, single source/view, Sentence root, permitted node kinds, required spans/origins, empty embeds/maps and same-head containment. Other-token, source-less or outside-origin data cannot be completed from ambient state. Field location checks also retain containment in the node span through the ordinary structural validator.

The lower dispatch first classifies the record kind, then invokes exactly one corresponding checked decoder; type identity is validated there. Merely spelling SentencePayload does not bypass its schema digest. No error branch retries legacy decoding. Owner selection uses the complete token SnapshotId against the owning bundle's sources. The joined result still requires exact outer token head and complete View equality, offsets local origin references, keeps caller-plus-surface depth and revalidates final structure. The code returns a local Result and does not mutate the original parse bundle on failure.

The new stock grammar/catalog uses doc.reader/sentence-v2 and operation sentenceReferenced, with ProviderSignature.value_output=SentencePayload. The original sentence operation is distinct. Generated descriptors preserve both operation identities; the selected schema digest and host identity bind the new implementation. The Doc schema generator intentionally skips a generic adapter for this specially scoped payload. This review does not claim the new stock host executes old provider operations: legacy support here is the explicit lower/DocumentSyntax path, as specified.

The core remains no_std/alloc; no new I/O, pointer identity in wire, source reconstruction by reparsing or limit increase is introduced. The stock helper still temporarily holds a one-source DocumentSyntax, but encoded tokens no longer include the owner's whole text. Lower's legacy source merge/full-text comparison remains a possible additional cost and is not claimed eliminated.

## Independent production-API execution

1. A new source containing CRLF before the literal, Kanji Ruby, Anno and escaped brackets plus escaped CR/LF was scanned through sentence::read. The returned head's original byte bounds and decoded literal Text `[x]` plus CRLF were checked. Owner tails2048 versus8192 bytes produced source lengths2078/8222 and exactly equal payload byte length16216, establishing independence from unrelated owner text length. This is not a claim that every small payload is smaller than its source.
2. Payload and explicit source declarations passed actual NDF/CBOR encoding/decoding into a fresh admission/empty-store receiver. Native DocumentSyntax equality held; admitting/decoding the same source repeatedly counted SourceBytes exactly once. With the correct source in ambient, explicit owners with a different name, revision or digest were rejected without stopping an otherwise sufficient Budget.
3. Work/Allocation/Source/Depth/Nodes caps0/1 and cancellation (12 cases) returned the original typed sticky StopReason without changing input. Fresh lower SourceBytes0 was separately rejected on both host routes; prior syntax validation did not authorize a free new operation.
4. New actual source `paragraph cons "[甲/こう]{a/n}" cons "乙" nil` followed by CRLF ran through both the per-token owned host and native host. Complete ParseTree equality held. Complete SyntaxBundle NDF/CBOR was decoded with no sender store and lowered to the same DocumentSyntax. Removing the outer wire source declaration and then performing first CBOR receipt with the correct source deliberately present in ambient was rejected on both routes.
5. Each host route exercised9 malformed branches: another token's payload; enlarged head; an independently valid empty internal View; semantic node span on another token; Direct origin on another token; source-less nodes; wrong payload schema digest; wrong record kind; and missing owner declarations. Modified payloads passed actual CBOR transport before validation/lower. All were rejected; no semantic error silently became a stop. For the relevant malformed narrow records, the explicit-owner codec also rejected first-received payload values directly. Exact kind mismatch and digest mismatch did not gain a legacy retry.
