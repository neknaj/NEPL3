## Defects found and rerun unchanged in meaning

The initial runner (`compare.py`, SHA `d7d852d10f545c847d1daaa361b28c801a95dd21f103f738b9a2ccf22c658a8e`) accepted malformed summary records with unknown result status, empty status plus positive count, or passed status without runs. An actual no-match `--exact` invocation executed zero tests but its aggregate still succeeded using an earlier positive record. A controlled subprocess-boundary experiment changed a real artifact copy during the second execution, and the runner reported passed without a final SHA check. A controlled unavailable executable left old success evidence intact. These observations are preserved in `boundaries.json` and the initial `cases/` records. The first attempt at that mock incorrectly intercepted the version subprocess too; the probe was corrected to supply the pinned version independently before recording the valid reproduction.

The next runner (`compare-after.py`, SHA `89aae8e4c8f75cdbbb7b811bcbc11ae42716e3f7febc34201ea125490e05e092`) corrected those cases using fresh sessions, unique invocation directories, failed preflight records and after-execution hashes. Its aggregate still ignored an unfinished invocation directory and accepted a summary-less log with matching updated hashes, boolean exit codes, and missing artifact identity. `after-checks.json` records those cases.

The final runner rejects all of these original cases (`final-checks.json`). The fresh epoch with only an actual empty invocation fails aggregation; previous sessions do not supply counts. The malformed-record, unfinished-directory, absent-summary, boolean-exit-code and missing-artifact-identity cases now reject. The second-execution mutation fails. Failed preflight creates a new failed invocation and the session aggregate fails. No unresolved blocking defect remains in these tested boundaries.

## Output, deadline and CI assessment

The independent controlled output matrix verified rejection of mismatched counts, absent or duplicated libtest summaries, differing stdout, differing stderr, and nonzero exit status; only elapsed-time differences normalize away. Empty library test binaries are accepted as `empty` with zero count, while a wholly empty current session cannot satisfy the aggregate. These are controlled subprocess results, not additional production-test passes. The shared final `test_count` function applies the same summary/count rule during execution and aggregation.

The runner retains 180-second whole-child-process deadlines and a 10-second version deadline. A controlled TimeoutExpired case records failure and partial stdout/stderr; it is not reported as a real 180-second expiry. Real process kill/reap behavior was separately demonstrated by the previous same-artifact watchdog experiment in `../review-pulley/deadline-control.json`. This review does not claim hard realtime termination. The CI job also retains its overall 20-minute deadline. The selected real runs completed normally within the independent outer limits.

The final CI command uses absolute script and evidence paths, initializes a fresh session, runs the four explicitly listed crates without test filters, then checks current-session evidence. The original relative paths were unsuitable for Cargo's package-root working directory; root separately reproduced and corrected that Cargo failure. The Cargo [working-directory contract](https://doc.rust-lang.org/cargo/commands/cargo-test.html#working-directory-of-tests) supports that distinction. The final step also runs the runner's regression tests and uploads evidence even on failure. The four-crate list is preserved; earlier broader WASI checks remain separate.

Root reported a full unfiltered Cargo comparison of 31 component invocations and 209 production tests per backend. Reviewer independently rechecks those completed result/log files with the frozen strict checker at evidence freeze and records the outcome in `root-results-check.json`. This is independent evidence validation, not a claim that reviewer reran the entire Cargo suite.

The evidence checker verifies structure, required identities, per-backend success, log hashes, normalized output equality and counts. It is not authentication of arbitrary externally forged JSON. The generated commands, fixed inputs and observed real subprocess runs supply provenance. The interpreter and native target still share Wasmtime and Cranelift infrastructure; this does not establish independent compiler implementations, RP2040 hardware execution, or latest-source-to-artifact reproduction. Those limits remain as recorded in `../review-pulley/review.md`.
