確認かくにんした不整合ふせいごうと方針ほうしん

  • r3のSourceRefはURI/revision/digestであったが、同おなじURIを持もつ二ふたつの独立どくりつしたmemory documentのSourceIdを区別くべつできず、spec02のsnapshot同一性どういつせいとspec13のbijectionが両立りょうりつしなかった。r4ではhostが与あたえるopaqueなTextのSourceIdをportable identityに含ふくめ、URIをSourceContentのlocatorへ分離ぶんりする。coreはIDを乱数らんすうや時計とけいから生成せいせいしない。

  • Limitsは許容最大値きょようさいだいちであり、観測かんそくしたUsageとは別型べつがたにする。depthは現在げんざいの再帰深さいきふかさと最大到達深さいだいとうたつふかさを区別くべつし、backtrackingで消費済しょうひずみworkを返却へんきゃくしない。

  • intrinsic NDF値ちの閉包へいほうから、domain descriptor・登録とうろく・値検査あたいけんさ・具体的ぐたいてきな操作そうさとframeへ進すすめる。型名かためいが解決かいけつしただけではR006を完了かんりょうしない。

  • 文書ぶんしょinventoryのDG01〜DG09を確認かくにんした。表ひょう・list・link・任意言語にんいげんごcode等とうをTextへの黙だまった縮約しゅくやくやRawHtmlで代用だいようせず、Doc schema拡張前かくちょうまえに具体化ぐたいかする。共通値きょうつうちやsourceの実装じっそうをこの未実装みじっそうdomainの成功せいこうstubで埋うめない。

前節ぜんせつまでの記録きろくは過去かこsliceの固定範囲こていはんいである。現在げんざいは通常つうじょうのCustom bindingを明示めいじhostへdispatchし、同おなじvalidatorを使つかう借用しゃくようFactsRequest、正式せいしきReport emitter、権限付けんげんつきdeltaの原子的適用げんしてきてきよう、疎そID、解決更新履歴かいけつこうしんりれきを実装じっそうした。元もとOccurrenceの発行はっこうstageを保存ほぞんし、before/afterの連鎖れんさと最終さいしゅうFactSetをnative/CBORで確認かくにんする。recursive Custom header/bodyのphase別契約べつけいやく、独立どくりつprocessの実じつFacts呼出よびだしと遠隔予算精算えんかくよさんせいさんは未完みかんとして残のこす。

AnalysisKeyに束縛そくばくした実定義じつていぎジャンプ・参照検索さんしょうけんさくを追加ついかした。元もとの7種類しゅるいの入力にゅうりょくに対たいするbyte位置いち、shadowing、Foreign、曖昧あいまいな全候補ぜんこうほ、escaped Text、Unicode境界きょうかいと半開終端はんかいしゅうたんを管理対象かんりたいしょうにし、source-lessなCustom Entity、疎そID、過去かこOccurrenceの明示更新後めいじこうしんごのqueryも実行じっこうする。通常つうじょうの名前探索なまえたんさくをquery側がわでやり直なおさない。QueryRequest初回受信しょかいじゅしんと返信へんしんsource閉包へいほうのCBOR往復おうふく、改変かいへんURI/ID/key/source表ひょうの拒否きょひ、停止理由ていしりゆうの保持ほじを検査けんさする。一般いっぱんfield/view region selector、rename、全ぜんeditor機能きのうやT06全体ぜんたいの完成かんせいはこの部分証拠ぶぶんしょうこから推定すいていしない。

次段じだん: Recursive Custom と単体たんたいForeign閉包へいほう

Recursive CustomのHeader/Body phaseと受理じゅりheader IDのprivate memoを実装じっそうした。実じつcompiler→parser→bindingにより相互再帰そうごさいき、静的宣言せいてきせんげんとの混在こんざい、同どうplan反復はんぷく、同名別どうめいべつEntity、Foreign独立どくりつroot、Unicodeを確認かくにんし、同期どうきNDF/CBOR初回受信しょかいじゅしんから同おなじcallbackを呼よぶ結果けっかも比較ひかくした。phase/receipt変異へんいと7資源しげんの停止ていしprefixは通常つうじょうのBindingReply codecで検査けんさする。外部がいぶFacts providerへの排他的はいたてきquota貸出かしだし・精算せいさんは後続こうぞくに残のこす。

ForeignClosureはguest syntaxと選択せんたくowner環境かんきょう・元もとOrigin/source/map表ひょうを保持ほじする。owner/guestで同数値どうすうちの環境かんきょうIDとOriginRefが別内容べつないようを指さす実じつCBOR往復おうふく、宣言せんげんsource欠落けつらく、環境かんきょうdigest偽造ぎぞう、外側そとがわschema/root不一致ふいっちと停止ていしを管理対象かんりたいしょうへ追加ついかした。非ひempty EnvironmentBindingで実証じっしょうされたNamespaceRef descriptorの混同こんどうをEnvironmentNamespaceRefへ訂正ていせいした（R046）。これは共通閉包きょうつうへいほうの検証けんしょうであり、Doc/Mathのlower・意味処理全体いみしょりぜんたいの完了かんりょうを示しめさない。

次段じだん: 実再じつさいparseに束縛そくばくしたrename

名前なまえOccurrenceを選択せんたくする二段にだんrenameを追加ついかした。元もとと候補こうほの両方りょうほうで実じつParseSession完了かんりょうproofと同おなじimmutable treeに対たいするkeyed Binding実行じっこうを要求ようきゅうし、private draftの候補こうほsource・同どうProfile/実装じっそう/options・構文形状こうぶんけいじょう・全確定ぜんかくていresolutionをacceptで照合しょうごうする。raw treeを変更へんこうしてprepareしただけの値あたい、別べつparse proofとの組替くみかえ、stale revision、未使用みしようのmap target末尾まつびbytesやURIの変更へんこうでは編集へんしゅうを公開こうかいしない。候補こうほを作つくる段階だんかいで元もとSourceStoreへ編集へんしゅうを適用てきようしない。

管理対象かんりたいしょうはLetのinitializer除外じょがい、shadowing/free nameの捕捉拒否ほそくきょひ、同どうscope衝突しょうとつ、予約よやくheadの所有しょゆうschema、Foreign独立どくりつEntity、Unicode/CRLF、Custom疎そIDと更新後こうしんごの最終さいしゅうresolution、位置いちなし、変換型へんかんがた/複数ふくすうsource/被覆穴ひふくあなの拒否きょひを含ふくむ。隣接りんせつExactを一意いちいな連続被覆れんぞくひふくへ結合けつごうし、全区間ぜんくかん・scalar分割ぶんかつ・逆表順ぎゃくひょうじゅんとUnicode長ながさ変更へんこうを実再じつさいparse→解析かいせき→accept→CBOR往復おうふくで比較ひかくする。完了かんりょうproofのread/resume/reserve/resume_head入口いりぐちは通常つうじょうのraw結果けっか・Report・Usageと比較ひかくし、非ひComplete枝えだからproofを発行はっこうしない。受信検査じゅしんけんさではold digest・書込元かきこみもと・key・非重複ひちょうふく・宣言せんげんsource欠損けっそんをschema-valid変異へんいで検査けんさし、停止理由ていしりゆうを保持ほじする。

このrename APIのReportはrename自体じたいの観測かんそくUsageだけで、診断しんだん/eventは元もとparse/analyzeの正式せいしきReportをcallerが保有ほゆうする。全段階ぜんだんかいのReportを集約しゅうやくする汎用外部はんようがいぶRename operation包絡ほうらくが完成かんせいしたとの主張しゅちょうではない。初回しょかいraw decoderは書込許可かきこみきょか・parse実行じっこう・意味対応いみたいおうのproofを発行はっこうせず、独立どくりつprocessの認証済にんしょうずみ実行じっこう/費用統合ひようとうごうは後続こうぞくに残のこる。任意にんいの逆ぎゃくencoder、一般いっぱんfield/view region selector、増分再解析ぞうぶんさいかいせき、T06全体ぜんたいの完成かんせいをこの範囲はんいから推定すいていしない。最終さいしゅうcross-targetと統括とうかつgateの結果けっかは当該とうがいcheckpoint記録きろくを正本せいほんとする。

次段じだん: field/View/reader sidecarのregion選択せんたく

Grammarの既存きそんstyle arityを保たもち、独立どくりつしたselection宣言せんげんからU64 priorityを生成せいせいする。Form/Leaf/HeadShapeの型かた・package identity・source位置付いちつき失敗しっぱいを同期どうきした。実元じつもとGrammarのP0/P1/P2と独立どくりつsource変異へんいを従来じゅうらいの10B Work上限内じょうげんないで検査けんさする。

prepared tree/Profileと明示めいじReaderFactBatchをRegionKeyへ束縛そくばくし、最小さいしょうrange・priority・包含深ほうがんふかさ・宣言順せんげんじゅんで選択せんたくする実じつAPIを追加ついかした。field、token内部ないぶView、Capture/Presentation、Foreign、回復かいふくnodeを区別くべつし、UnknownHeadのarityを捏造ねつぞうしない。表示用ひょうじようSourceMapはowner局所きょくしょで、Exactの分割同値ぶんかつどうち、部分被覆ぶぶんひふく、Transformed、多義性たぎせいを保持ほじする。token.leadingTriviaの再掲さいけいとCaptureのmapped containmentは既存きそんreader契約けいやくで検査けんさする。

管理対象かんりたいしょうは実じつparserからのfield priority、nested View、生成せいせいsource Capture、消費範囲外しょうひはんいがいの正式せいしきPresentation、改変かいへんtrivia/owner/revision、Foreign/escaped Text/Unicodeの独立どくりつCBOR初回受信しょかいじゅしん、要求ようきゅう/返信変異へんしんへんい、回復かいふく・UTF-8境界きょうかい・stale key・停止ていしを含ふくむ。最終さいしゅうnative/WASI/統括とうかつgateの実行結果じっこうけっかはcheckpoint記録きろくに分離ぶんりする。この最初さいしょのregion単位たんいの出力しゅつりょくは元もとoverlapとclassを保持ほじしたhighlight材料ざいりょうであり、一般いっぱんregionから既存きそんdefinition/referencesへの接続せつぞくは次節じせつに分わけた。LSP向むけ非重複ひちょうふく・単行化たんぎょうか、completion、増分解析ぞうぶんかいせきは後続こうぞくである。raw sidecarやRegionReplyからprovider実行じっこうや完了かんりょうBindingのproofを発行はっこうしない。

次段じだん: 選択せんたくregionと確定かくていBindingのquery接続せつぞく

RegionQueryはpriorityで選択せんたくしたlogical regionと正準せいじゅんbundle所有しょゆうを保持ほじし、実じつBindingが発行はっこうしたbundle/root ScopeId対応たいおうから候補こうほOccurrenceを絞しぼる。Foreign fieldの内容ないようはguest rootへ対応たいおうし、同どうsource上じょうのhost宣言せんげんを誤参照ごさんしょうしない。owner局所きょくしょのExact/Transformed双方向関係そうほうこうかんけいで位置いちを対応付たいおうづけ、非一意ひいちいな対応たいおうの候補こうほを保持ほじする。各かくDefinition/Referencesは既存きそんの確定かくていresolution処理しょりを共有きょうゆうし、Custom更新後こうしんごの疎そIDやsource-less targetも維持いじする。

Customの受理じゅりmapはemitter/deltaの受理時点じゅりじてんでbundle所有しょゆうindexを同時どうじに保存ほぞんする。実じつhost/guestが同おなじ生成せいせいsourceを共有きょうゆうする入力にゅうりょくで各定義かくていぎへの到達とうたつとguest mapのhostへの非漏出ひろうしゅつを検査けんさし、初回しょかいCBOR要求ようきゅうから実じつproviderを再実行さいじっこうしたBinding結果けっかでも一致いっちする。途中停止とちゅうていしでmapと所有しょゆうの片方かたほうだけを公開こうかいしないこと、raw indexの範囲外はんいがい・重複拒否ちょうふくきょひも管理対象かんりたいしょうに含ふくむ。

既存きそんrenameが平坦へいたんなmap表ひょうを探索たんさくし、guest-only mapによってhost名めいの編集先へんしゅうさきをaux sourceへ選えらべた問題もんだいも同おなじ所有契約しょゆうけいやくで修正しゅうせいした。各かくOccurrence/Entityの逆写像ぎゃくしゃぞう、各元編集かくもとへんしゅうとownerの組くみに対たいする前向まえむき導出どうしゅつ、old/new側がわの位置比較いちひかくを局所化きょくしょかする。実じつsealed lambda x guest x のguest reader返信へんしんにだけaux→host Nameを宣言せんげんした反例はんれいはaux-only writableで拒否きょひし、host writableの正常編集せいじょうへんしゅうと、Customが返かえした生成名せいせいめいからのemitter/delta両経路りょうけいろの正常せいじょうrenameを実再じつさいparse・再さいBinding・CBORで検査けんさした。

原げんLetのinitializer/body、nested Lambda、Foreign field priority、日本語位置にほんごいち、実じつproviderが宣言せんげんした複数ふくすうExact/Transformed候補こうほ、停止ていし・stale key・source/候補改変こうほかいへん、bundle/root対応たいおうの不正受信ふせいじゅしんを管理対象かんりたいしょうへ追加ついかした。元もとRust要求ようきゅうを受うけ取とらないCBOR初回受信しょかいじゅしんから実じつBindingを行おこない、nativeの選択せんたくと候補こうほ・sourceを比較ひかくする。raw metadataや返信へんしんcodecは意味いみproofを発行はっこうしない。LSP用ようhighlight正規化せいきか、completion、増分解析ぞうぶんかいせき、外部がいぶprocess認証にんしょう・費用統合ひようとうごうは別項目べつこうもくに残のこり、この接続せつぞくからT06全体ぜんたいの完成かんせいを推定すいていしない。
